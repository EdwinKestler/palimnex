# Palimnex 2.6 capabilities

Status: release candidate `2.6.0-rc.1`.

Palimnex 2.6 promotes two related capability sets: evidence-aware context and
capture, and explicit local retention with authorized erasure. SQLite schema
v1, Redis cache v3, encrypted pack v2, and the existing `project-memory:*`
serialized identifiers remain compatible.

## Evidence-aware context

- Recall can restrict sensitivity, retention, visibility, and session scope
  before applying its result limit.
- Strict claim support is an exact, auditable source quotation. A matching
  source digest proves byte integrity, not truth or entailment.
- Capture is previewed before an explicit, idempotent apply closes the session.
- Capsules are read-only derived evidence extracts that retain parent event,
  source digest, conflict, and omission metadata.
- Context combines source evidence and eligible historical records within an
  explicit byte budget. Imported history remains untrusted.

Versioned envelopes remain `project-memory:context:v1`,
`project-memory:capture:v1`, `project-memory:claim:v1`, and
`project-memory:capsule:v1`.

## Retention and erasure

Durable records are never forgotten automatically. Imported records may be
forgotten only under an explicit retention, source-synchronization, privacy,
or legal-erasure policy. Derived facts remain only when at least one supporting
source survives and recomputed confidence meets policy threshold.

Erasure is an orchestrated local transaction:

1. authenticate and authorize the request;
2. resolve the source and local derivatives;
3. enforce legal holds and protected anchors;
4. delete eligible content, graph data, vectors, indexes, and cache material;
5. recompute or withdraw dependent facts and relationships;
6. verify every supported local backend;
7. write a non-reconstructive, hash-chained audit tombstone.

Managed packs and previously attempted Redis projections fail closed until a
verified invalidation or regeneration adapter exists. Local compaction cannot
prove erasure from storage media, backups, snapshots, external systems, or
unmanaged exports. See `docs/RETENTION.md` for the exact contract.

## Operator commands

```bash
python3 palimnex.py context "source evidence correction" --backend local
python3 palimnex.py capsule "source evidence correction" --session SESSION_ID
python3 palimnex.py capture-preview SESSION_ID SPEC.json
python3 palimnex.py capture-apply CANDIDATE.json
python3 palimnex.py retention-status
python3 palimnex.py evaluate-challenges
```

All write commands remain explicit. Installation, indexing, validation, and
evaluation do not activate a retention policy or erase data.

## Acceptance gate

`scripts/palimnex_check.sh` runs the unit/adversarial suite, development
challenge evaluation, longitudinal offline replay, and an isolated Redis
index/deep-validation/frozen-retrieval gate. It never reads or mutates the live
ledger and makes no model call. GitHub Actions invokes the same script.
Frozen ranking interpretation for this corpus is in `docs/DESIGN.md` section 10.
